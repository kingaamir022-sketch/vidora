Everything in it is Vidora Original: the music, clips, images and voices are generated by Vidora's own local generators (`generation/`), no sign-in, no credits, no third-party models. ## Interactions
- Click a sub-tab: the panel switches section (search + chips reset to All).
- Click ▶ on a music row: the MP3 plays; clicking again (or another row's ▶) stops it. Click +: a MediaItem (kind audio, src `/ai-library/music/<id>.mp3`, duration/BPM/key/peaks from `assets/ai-manifest.json`) is added and an audio clip is placed on the first free audio track.
- Click + on a clip card: a MediaItem (kind video, src `/ai-library/clips/<id>.mp4`, 1920×1080, 6 s, poster thumbnail) is added and placed on the timeline.
- Click + on an image card: a MediaItem (kind image) is added and placed on the timeline.
- Voices sub-tab: see O-AI-VOICES. Generate sub-tab: see O-AI-GENERATE.
- Missing file: music rows fall back to in-browser Web Audio rendering of the same pattern (`renderAiTrack`); clip/image rows show the Drive note and their + button is disabled.

## States
- Empty search: "No AI assets match this search."
- Loading: none (catalog is bundled JSON; files load on demand).
- Error: a file that fails to load shows "Could not load — try the in-browser version" (music) or the Drive note (clips/images).

## Result
The selected item appears in the Media panel and as a clip on the timeline, ready to edit like any imported media.

## Edge cases
- No network: everything still works — the library is local files, no downloads.
- Text-only checkout (no `public/ai-library/` files): music still works via synthesis; clips/images show the Drive note.
- Very long track (60 s) added to a short project: the clip extends the timeline as usual; trim works normally.
